# Domain docs

## Layout

Use a single-context layout:
- `GLOSSARY.md` at the project root for domain terminology.
- `docs/adr/` for architectural decision records.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
For a missing concept, check existing project language before
recording a terminology gap for domain-modeling.

## Decision conflicts

Explicitly flag proposals that contradict an existing ADR.
Identify the ADR and explain why the decision should be reopened.
