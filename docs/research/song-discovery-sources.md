# Song Discovery: online source assessment

Checked 23 November 2026. This is research for the online-catalog flow in ADR 0001, not a provider decision or implementation. No audio was downloaded. Metadata and HTTP HEAD probes are small samples, not catalog-coverage measurements.

## Recommendation

The subsequent design decision selects yt-dlp with YouTube for the first integration, with an audio-only preview and file upload as the fallback. The comparisons below document the alternatives considered. Full audio retrieval and preview on the GCP VM still need verification.

### yt-dlp with YouTube search

The installed yt-dlp 2025.12.08 returned plausible matches among the first three search results for all five examples in a local metadata-only check. Frank Sinatra's channel surfaced “Fly Me to the Moon” after a compilation. The Arabic Fairuz query returned UMMENAVEVO lyric videos. The artist-qualified Sade query returned a 1984 video and a 2011 remaster, with missing channel metadata. Searching “Perfect Ed Sheeran” ranked a LatinHype result above Ed Sheeran's own video. Searching “عمر دياب” surfaced Rotana's “Khalik Maaya” first. Results can vary by region and time. This checked discovery on the workstation; playback, audio extraction, and deployment on GCP remain untested.

yt-dlp can resolve a selected video and hand its audio to FFmpeg. Its YouTube extractor depends on a changing upstream service. Evaluate file retrieval on the deployment VM with a source that explicitly allows automated downloads before making it a station dependency. YouTube's standard terms restrict automated access and downloading, and an official artist upload alone does not establish approval for a permanent radio-library copy. [yt-dlp](https://github.com/yt-dlp/yt-dlp), [YouTube terms](https://www.youtube.com/static?template=terms).

Internet Archive was an alternative for file discovery and import. Each of the five representative searches yielded a plausible, publicly reachable MP3. Community metadata and HTTP headers establish candidate matches, and a successful preview and import still need to be tested. Deezer is a useful comparison for ranking and identifying versions. [Archive metadata API](https://archive.org/developers/md-read.html), [Sade single metadata](https://archive.org/metadata/smoothoperatorsingle).

## Provider-specific findings

### Incompetech: a concrete baseline

The main research session fetched the official JSON and observed **1,443 catalog rows**. `Local Forecast` had duration `00:02:45`; HEAD on its documented MP3 URL returned HTTP 200 and content length 6,611,177 bytes. This confirms a full-recording file is technically reachable without downloading it; decoding, loudness preparation and audible preview remain untested. Use the returned `filename`, safely URL-encoded, beneath the documented MP3 directory. [Catalog JSON](https://incompetech.com/music/royalty-free/pieces.json), [Local Forecast MP3](https://incompetech.com/music/royalty-free/mp3-royaltyfree/Local%20Forecast.mp3), [directory and field documentation](https://incompetech.com/agent-section/).

### Audius: broader search, conditional downloads

The main session's keyless searches returned three results each. For `oud`, one was downloadable and two streamable; for `instrumental jazz`, all three were streamable but none downloadable. `ChiefDijon — Lesson Two: Joel's Oud` (`RpXxAEQ`) had `access.download=true` with no download conditions. HEAD following its download endpoint returned 302 then 200, `audio/mpeg`, 10,889,407 bytes. This is technical evidence for one downloadable recording, not evidence of broad Arabic coverage or station-use permission. Ordering and flags can change. [Oud query](https://api.audius.co/v1/tracks/search?query=oud&limit=3), [jazz query](https://api.audius.co/v1/tracks/search?query=instrumental%20jazz&limit=3), [track metadata](https://api.audius.co/v1/tracks/RpXxAEQ), [download endpoint](https://api.audius.co/v1/tracks/RpXxAEQ/download).

An additional illustrative artist query, `Fairuz`, returned mixes/remixes and other results with **0/5 downloadable**. This artist was a research example, not an applicant-selected demo requirement. Artist matching and useful import coverage need to be checked against the applicant's actual songs. [Fairuz query](https://api.audius.co/v1/tracks/search?query=Fairuz&limit=5).

Current SDK documentation advertises a free API-key plan at **10 requests/second and 500,000 requests/month**; the REST overview says most read endpoints work without credentials. The observed keyless response agrees with that narrower claim; register a production key rather than relying on unspecified anonymous limits. [SDK plans](https://docs.audius.co/sdk/), [REST authentication](https://docs.audius.co/api/).

**Unresolved terms distinction:** Audius Service terms dated October 2025 restrict downloading/local serving, but also distinguish third-party protocol access governed by API Terms and the Open Music License. The official July 2025 announcement confirms that distinction and artist restrictions. Therefore the Service restriction alone does **not** conclusively prohibit the documented API download route. This research did not retrieve the complete API Terms/OML, so it does not establish permission for the intended permanent MP3 library and restaurant broadcast. [Terms, especially pp. 18 and third-party content provisions](https://audius.co/documents/TermsOfUse.pdf), [official API/OML explanation](https://blog.audius.co/posts/audius-terms-of-service-update).

### Jamendo: API fit differs from station-use fit

For track search, use `type=single albumtrack` because the default excludes singles; select relevance ordering, and only offer import when `audiodownload_allowed=true` with a nonempty download URL. Page size is at most 200. The developer site advertises up to **35,000 API requests/month** for noncommercial apps; terms also reserve additional limits. This research did not use a registered client ID or claim a successful live Jamendo query. [Tracks reference](https://developer.jamendo.com/v3.0/tracks), [developer plan](https://developer.jamendo.com/v3.0), [terms §3.3](https://devportal.jamendo.com/api_terms_of_use).

The standard terms allow free noncommercial API use, require contacting sales for other uses, constrain caching/offline-oriented applications, and require artist/provider credits plus track backlinks. Restaurant programming and retaining each selected recording permanently are material constraints for ADR 0001, even if downloads are enabled. Jamendo's own radio API warns that direct or indirect commercial use needs a commercial license. Its catalog synchronization license also excludes direct standalone audio streaming/compilation uses; buying a generic video license is not a demonstrated solution. Obtain a station-specific agreement covering API access, storage and broadcast if selecting it. [API terms §§3.3,4.1](https://devportal.jamendo.com/api_terms_of_use), [radio API warning](https://developer.jamendo.com/v3.0/radios), [licensing sale terms](https://licensing.jamendo.com/en/legal/termsofsales).

### Internet Archive: test the actual recording, not just the item

The main session queried `mediatype:audio AND title:"oud"`; results included Dutch “Oud-Hollandsch” material. Item `calauem_000449` contained two approximately 46-minute program MP3s and `access-restricted-item=true`. This illustrates ambiguous language matches, program-length results and restrictions; it does not establish that all Archive music is unsuitable. A usable adapter needs exact file selection, a track-level identity and rights evidence. [Live metadata example](https://archive.org/metadata/calauem_000449), [Archive item model](https://archive.org/developers/).

## Implications for the existing design

Online results are separate from the music library. A provider ID, title, artist, duration, and preview/download availability can identify the selected recording. Recheck download availability when the manager requests an import and use the agreed duplicate and FFmpeg checks.

The project has chosen title-and-artist credits. Incompetech's published CC BY 4.0 terms call for additional attribution information, so compatibility with that choice is an open provider-selection question. [CC BY 4.0 conditions](https://creativecommons.org/licenses/by/4.0/), [Incompetech catalog terms](https://incompetech.com/agent-section/).

## Internet Archive: five requested catalog searches

Live checks on 23 November 2026 found a technically accessible MP3 candidate for **each of the five requested searches**. Searches used the official `advancedsearch.php` JSON interface, `mediatype:audio`, artist/title fields, and 5–8 results per query. Follow-up used official `/metadata/{identifier}` responses and public download URLs with **HEAD only**, following ordinary redirects. No account, audio download, audition or access-control bypass was used. Every candidate in the table returned **302 → 200**, `Content-Type: audio/mpeg`, with the stated content length. This establishes public HTTP availability at check time; decoding, audio quality, full recording identity and broadcast permissions were not established. Internet Archive items can hold multiple files, so the selected file matters. [Archive item model](https://archive.org/developers/), [metadata API](https://archive.org/developers/md-read.html).

**Revised technical assessment:** Internet Archive is a viable candidate for the intended in-app artist/title search, optional preview and manager-selected import flow for these examples. The earlier `oud` result was an unrepresentative negative sample. The integration would need to expose recording/version details, select the actual audio file, and retain the upload fallback. These probes do not authorize the listed recordings for the public restaurant broadcast: Internet Archive does not assert new copyright rights over hosted material, and uploader labels cannot establish those rights. [Archive licensing statement](https://archive.org/developers/#licensing).
